# Windows 后台运行

先在前台验证 `npm start` 正常，再设置后台入口。以下方式选一套即可，避免同一事件被多个监听器重复处理。

## VBS 入口

- `一键启动.vbs`：重新启动当前目录对应的统一监听器。
- `看监听状态.vbs`：查看监听状态。
- `装进任务计划程序.vbs`：注册 `band-notify-watchers` 计划任务，由 `tools/watchdog.vbs` 检查并拉起监听。

脚本使用自身目录和当前用户目录解析路径，没有固定电脑用户名。VBS 文件保留 UTF-16LE BOM 与 CRLF，便于 Windows Script Host 读取中文。

这些入口需要系统允许 Windows Script Host / VBScript。企业策略、Windows 可选组件和本机安全设置可能限制运行。静态检查通过不代表每种系统策略下都能启动，安装后要用状态命令确认进程和心跳。

## 不使用 VBS

可一直保留运行 `npm start` 的窗口，也可以手动在 Windows 任务计划程序中创建基本任务：

1. 用 `where.exe node` 找到已安装的稳定 Node.js 路径。优先使用独立安装的 Node，不要填写智能体 App 内带版本号、升级会删除的运行时路径。
2. 触发器选择当前用户登录时。
3. 操作选择“启动程序”，程序填写自己的 `node.exe` 路径。
4. 参数填写项目 `tools\agent-watch.js` 的完整路径，路径带空格时加双引号。
5. “起始于”填写项目根目录。
6. 选择仅在用户登录时运行；如果任务已在运行，选择不启动新实例。
7. 先关闭手动启动的监听窗口，运行任务，再执行 `npm run status` 核对。

手动方案运行的是监听器本体。自动异常重启等策略需要在任务设置中自行配置，不能等同于 VBS watchdog 的定期检查。

## 迁移和停止

前台启动的监听器用 Ctrl+C 关闭。后台方案先禁用对应计划任务或启动项，再按命令行完整路径识别进程，只停止自己这份项目的 `agent-watch.js`，不要批量终止所有 Node 进程。

从旧目录迁移时，先确认旧入口已经停止，再安装新入口；配置文件需要保留你自己的服务器、频道和令牌，不能从别人仓库复制真实频道。
