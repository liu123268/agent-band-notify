# 手机与手环设置

## 收通知的链路

电脑不直接控制手环。通知先由 ntfy Android App 接收，再由小米运动健康等配套 App 按应用通知转发。只要手环支持转发第三方应用通知，就可以按这个思路配置；不同品牌的菜单和行为可能不同。

## 手机端

1. 通过 [ntfy 官方入口](https://docs.ntfy.sh/subscribe/phone/) 安装 Android App。
2. 在电脑项目目录执行 `npm run setup`，查看输出的服务器和随机频道名。
3. 打开 ntfy，添加订阅，填写相同服务器和频道名。频道一栏通常只填名称，不填完整 URL。
4. 允许 ntfy 的通知权限。需要明显提醒时，检查对应通知渠道的声音、振动和优先级。
5. 按手机系统设置允许后台联网、自启动，并解除可能阻止通知的电池限制。菜单位置由手机系统决定。
6. 使用自建且受保护的 ntfy 服务器时，也要在手机端配置订阅所需的账号或访问权限。

默认配置的 ntfy 优先级为 4；Android 对该级别通常显示高优先级通知，但系统勿扰和通知渠道设置仍然生效。详见 [官方优先级说明](https://docs.ntfy.sh/subscribe/phone/#message-priority)。

## 手环端

1. 确认手环已与手机正常配对，配套 App 可以连接设备。
2. 在配套 App 的设备设置中找到“应用通知”“消息提醒”或同类设置。
3. 打开 ntfy 的转发权限。小米方案一般在“小米运动健康”中设置。
4. 根据手机提示授予配套 App 读取通知的权限。
5. 检查手环勿扰、睡眠模式，以及“仅在佩戴时提醒”等选项。

不要因为手机通知能响就直接判定手环链路已通：它们属于两段不同的链路。

## 分段验收

在电脑项目目录运行：

```powershell
node notify.js --test --json
```

依次检查：

1. 终端输出 `ok: true`：ntfy 服务器已接受请求。
2. 手机出现 ntfy 通知：服务器到手机的订阅与后台通知正常。
3. 手环显示通知或振动：配套 App 的转发和手环设置正常。
4. 再运行 `npm start`，在支持的软件里完成一个新任务，确认自动提醒链路。

## 排错

| 现象 | 优先检查 |
| --- | --- |
| `ok: false` / 请求超时 | 电脑是否能访问配置的服务器；URL、令牌和服务器权限是否正确 |
| `ok: true`，手机无通知 | 服务器与频道是否完全相同；手机 ntfy 是否有通知和后台联网权限 |
| 手机有通知，手环不振动 | 配套 App 是否允许 ntfy；通知读取权限、蓝牙连接、手环勿扰是否正常 |
| 手动测试正常，软件完成却无通知 | `npm run status` 是否找到软件数据，是否只运行一个监听器，日志是否显示解析或发送异常 |
| 相同事件出现两条通知 | 关闭多开的前台窗口；核对计划任务和启动文件夹是否各有一套监听 |
| 升级软件后不再提醒 | 数据目录或日志格式可能变化；用状态输出和适配器测试定位问题 |

排错截图和公开问题中请隐藏自己的频道名、访问令牌及消息正文。
